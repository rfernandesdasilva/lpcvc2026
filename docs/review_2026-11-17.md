## 4. INT8 diagnosis (experiment 008)

Recap of 008: AI Hub default post-training quantization (min-max, 256 calibration images / 512 captions). **w8a8**
collapsed every encoder. **w8a16** was nearly lossless in onnxruntime simulation for B image (−0.01), S0 image (−0.67)
and S0 text (−0.32), but collapsed for **B text (4.76)**. On the S22, only B image w8a8 ran; the S0 image failed to
compile (31 subgraphs) and every other compiled graph failed on device with `MODEL_GRAPH_ERROR`.

### 4.1 B's text tower collapse: the `-inf` causal mask (verified)

- open_clip builds the causal mask as `torch.full((77, 77), float("-inf")).triu_(1)`. Every text block exports it as
  a 77×77 constant with `-inf` above the diagonal (`/text/transformer/resblocks.N/attn/Constant_5`), added to the
  attention scores before softmax.
- In the downloaded QDQ models, AI Hub's quantizer gave that mask tensor **scale 4.769e-10, zero-point 0 (uint16)**
  at w8a16, and 1.25e-07 (uint8) at w8a8. The representable range is [0, ~3e-5], so the `-inf` entries clamp to 0
  and **the causal mask disappears**.
- The `scores + mask` output (`attn/Add_3`) gets the **same** scale and zero-point, so every attention score is
  squashed into [0, 3e-5]. Softmax becomes uniform: every token attends equally to all 77 positions, padding
  included. That explains why B text collapses even with 16-bit activations, while S0's text tower (no causal mask,
  `no_causal_mask=True`) loses only 0.3.
- This replaces the "plausible cause, not verified" note in the 008 README with a measured root cause.

### 4.2 Latency ceiling: ~5% (measured)

- The "fp32" QNN models already run in **FP16** on the S22 NPU, so INT8 is measured against FP16, not FP32.
- B image, FP16 (004) vs full w8a8 (008): **14.43 → 13.71 ms, −5%**. Summed per-op NPU cycles fell 42%
  (58.6M → 34.2M), but wall time barely moved. The ops overlap or something outside the op cycles dominates;
  **why** is not established.
- Where the FP16 cycles go (B image, summed per-op cycles): **exact (erf) GELU 36%**, attention matmul/softmax 23%,
  qkv/proj 12%, MLP 11%, LayerNorm 9%. Each block's GELU costs ~1.6M cycles in FP16 versus ~0.16M as an INT8
  lookup table. This motivated the GELU check in section 6.

### 4.3 What INT8 does buy: memory and size (measured)

- Peak inference memory, B image: **166 → 101 MiB (−39%)** at w8a8 (008 profile, `estimated_inference_peak_memory`).
- Model weights: 8-bit weights are about 4× smaller than FP32 ONNX (B image ONNX 330 MiB). The QDQ ONNX on disk is
  not smaller (331 MiB), because it stores float weights plus quantization parameters. The compiled on-device size
  was not recorded; record it before quoting a number.
- For the report: quantization is a memory/size lever on this device, not a latency lever.

## 6. Results of the follow-up runs

Code: commit `f3d9f6f` adds model flags (`lpcvc/models.py`): `+fmask` (causal mask clamped to −100), `+gelutanh`
(`nn.GELU(approximate="tanh")`), `+gelusig` (QuickGELU, `x·sigmoid(1.702x)`), plus `--encoders` for
`scripts/aihub_quantize.py`.

### 6.1 Finite causal mask

**FP32 accuracy (exp 024, fine-tuned B):** identical on every set: RefCOCOg-LPCVC 87.28, grouped 68.13,
sample 91.37, paired delta +0.00 [+0.0, +0.0]. Text embeddings match the `-inf` mask to cosine 1.000000. −30 is
also exact; −10 is not (text cosine drops to 0.29). So masked scores reach below −10 relative to the row and −100
leaves a wide margin.

**Quantization (exp 022, pretrained B text encoder, AI Hub PTQ, same calibration set as 008; accuracy from
onnxruntime on the QDQ models):**

| B text encoder | `-inf` mask (008) | finite mask −100 (022) | FP32 |
|---|---|---|---|
| w8a16 | 4.76 | **71.28 (−0.03 [−0.3, +0.2])** | 71.31 |
| w8a8 | 1.50 | 1.29 | 71.31 |

- **The mask fix fully rescues w8a16.** The new quantized graph gives the mask scale 1.53e-3 (range [−100, 0]) and
  `scores + mask` scale 2.15e-3 (about [−111, +30]), instead of 4.8e-10 for both. This confirms the root cause
  in section 4.1.
- **w8a8 stays collapsed.** 8-bit activations fail for other reasons (residual outliers around ±500; masked scores
  at a 0.55 step). That needs options 4–6 in section 5, not a graph fix.
- **Neither graph runs on the S22.** Both compiled, then failed with the same `MODEL_GRAPH_ERROR` as every quantized
  text encoder in 008, including S0's, which has no mask. The on-device failure is a separate, still-unexplained
  problem (suspects: the integer EOT-padding and ArgMax pooling ops, the int64 token Gather, the qnn_dlc runtime).

### 6.2 GELU approximations

**FP32 accuracy, no retraining (exp 024, fine-tuned B; paired delta vs erf GELU):**

| Variant | RefCOCOg-LPCVC | Grouped | LPCVC sample | Embedding cosine vs erf (min, img/txt) |
|---|---|---|---|---|
| erf GELU (submission) | 87.28 | 68.13 | 91.37 | — |
| tanh GELU | 87.28 (+0.00 [+0.0, +0.0]) | 68.14 (+0.01 [−0.1, +0.1]) | 91.37 (+0.00) | 0.99998 / 0.99999 |
| sigmoid GELU (QuickGELU) | 86.52 (**−0.75 [−1.4, −0.1]**) | 66.98 (**−1.15 [−1.9, −0.4]**) | 91.64 (+0.27 [−0.9, +1.5]) | 0.94 / 0.98 |

tanh GELU is a free swap. QuickGELU costs ~1 point without retraining; a short fine-tune with it in place would
likely recover that, but only if its latency gain justifies the run.

**S22 latency (exp 023, fine-tuned B, same-session control; median of 3 profiles, 100 iterations each):**

| Variant | Image ms | Text ms | **Total ms** | GELU cost, block 3 (cycles) |
|---|---|---|---|---|
| erf GELU (control; 011 measured 17.68) | 14.41 | 3.26 | **17.67** | 1.64M (fused `Gelu` op) |
| tanh GELU | 14.43 | 3.26 | **17.69** (+0.02) | 1.63M (fused into the same `Gelu` op) |
| sigmoid GELU (QuickGELU) | 12.64 | 2.84 | **15.48 (−2.19, −12.4%)** | 1.04M (Sigmoid + Mul, not fused) |

- **tanh GELU is a no-op on the device.** The QNN converter recognizes both the erf and the tanh pattern and emits
  the same fused `Gelu` op, so there is nothing to gain.
- **QuickGELU is 12% faster** on both towers (image −1.77 ms, text −0.42 ms). On the HTP, Sigmoid + Mul is cheaper
  than the fused `Gelu` kernel. Peak memory and ONNX size are unchanged.
- Its accuracy cost without retraining is about a point on our validation sets. A fine-tune with QuickGELU in place
  (the 010 recipe, ~22 min) should tell whether the loss disappears. Not run yet.

### 6.3 What changes

1. **Quantization is now a diagnosed result for the report, not just a failure.**
   - The B text collapse had a single verified cause, the `-inf` mask, and a lossless fix (w8a16 −0.03).
   - 8-bit activations remain out of reach without outlier handling.
   - The latency ceiling is ~5% because the baseline is already FP16.
   - INT8's real benefit is memory: −39% peak memory for B image.
2. **The on-device `MODEL_GRAPH_ERROR` is the next blocker** for any quantized text encoder (option 3 in section 5).
   Worth a time-boxed half day only if the report needs a quantized model running on the phone.
3. **The NPU-friendly activation finding is more valuable than INT8.**
   - Swapping erf GELU for QuickGELU cuts **2.19 ms (−12.4%)** from fine-tuned B on the S22 (17.67 → 15.48 ms), more
     than full INT8 saved on the image tower alone (−0.72 ms).
   - Its accuracy cost is about a point without retraining.
   - tanh GELU is a no-op, because the compiler fuses it into the same `Gelu` op as erf.
   - The next experiment is a fine-tune of B with QuickGELU in place (010 recipe, ~22 min), then the same check on
     S0, whose image tower has 30 erf ops.
   - This also fits the topic's "quantization-friendly architecture changes" directly.
4. Updated ranking: QuickGELU fine-tune (new, low effort, measured −12% latency) goes alongside idea #1 (pruning +
   distillation) at the top of section 3. Quantization options 4–8 stay below them.
